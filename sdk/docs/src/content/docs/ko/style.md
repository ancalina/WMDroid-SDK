- 현재 source로 선언, 조건, 반환, 오류를 확인하세요. 불확실한 필수 정보는 `확인 필요`로 표시하세요.
- 가이드는 목적별로 구성하세요. API 이름은 클래스 참조에 연결하고 정확한 시그니처, API별 계약은 참조에 유지하세요.
- 식별자, 코드, 수치, 단위, 기본값, 필수/금지 조건을 보존하세요.
- thread, 비동기, 소유권, 수명, 권한 제약은 생략하지 마세요.
- 공유 제약은 한 번만 쓰고 API별 차이만 추가하세요.
- 한 문장에는 한 개념을 쓰세요. 주체, 조건, 대상, 단위, 순서, 반환 의미를 보존한 완결된 문장으로 쓰세요.
- 순서가 필요한 작업만 번호 목록으로 쓰세요.
- 사용자가 실행, 결과 해석, 오류 진단에 필요한 설명과 예제는 남기세요. 조건이 다르면 문장을 나누세요.
- API 수정 없이 한, 영 페이지, Javadoc, 코드, 링크를 함께 갱신하세요.

| 논리 픽셀 | logical pixel | 전체 화면 배율 전의 UI 좌표 |
| 리소스팩 | resource pack | 검증된 데이터 ZIP |
| 호스트 | host | module 표시, 셸 상태를 제공하는 런처 |
| 스냅샷 | snapshot | 특정 시점의 변경되지 않는 데이터 묶음 |
